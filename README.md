# AI 小说写作助手（纯静态 HTML 版）

一个不用装 SDK、不用编译的单页 Web App：手机浏览器打开就能用，所有数据存在本机 localStorage，API Key 只保存在你自己的设备上。

## 从 GitHub 下载到 Termux

```bash
pkg update && pkg install -y git python
git clone https://<你的TOKEN>@github.com/ESStudio-AndL/ai-novel-writer.git
cd ai-novel-writer
python3 -m http.server 8080
```

然后在手机浏览器打开 `http://127.0.0.1:8080`。

本仓库是**私有**的，所以 `clone` 需要 token：到 <https://github.com/settings/tokens> 生成（Fine-grained 选这个仓库、Contents = Read and write 即可）。嫌麻烦可以把仓库改成公开，`git clone https://github.com/ESStudio-AndL/ai-novel-writer.git` 不带 token 就能拉。

以后我这边更新了，在 Termux 里一条命令同步：

```bash
cd ai-novel-writer && git pull
```

> 数据是存在浏览器 localStorage 里的，按 **origin + 端口** 隔离。建议一直用同一个端口（比如 8080），换端口会看到空书架。

## 在 Termux / 手机上跑起来

```bash
cd novel-writer
python3 -m http.server 8080
# 手机浏览器打开 http://127.0.0.1:8080
```

或者任意静态服务器（`npx serve`、`busybox httpd -p 8080` 都行）。  
也可以直接用浏览器打开 `index.html`，但部分浏览器对 `file://` 页面的本地存储有限制，**建议用 http 方式访问**（Termux 里一条命令即可）。

> 手机和 Termux 是同一台设备，所以 `127.0.0.1` 就能访问。若要在电脑上访问手机上的服务，用 `python3 -m http.server 8080 --bind 0.0.0.0`，然后访问手机局域网 IP。

## 底部主导航

底部常驻三个分页按钮（阅读页自动隐藏，把底部让给阅读工具条）：

| 按钮    | 路由           | 做什么                                               |
| ----- | ------------ | ------------------------------------------------- |
| 📚 书架 | `#/books`    | 新建 / 选择书本，菜单可重命名、复制、导出、删除；顶部搜索框可全文检索全部作品，卡片显示写作进度 |
| 🕘 最近 | `#/recent`   | 每本书一张卡片，记住你最近阅读或编辑的那一章，点一下直接回到该处                  |
| 📥 导入 | `#/import`   | 粘贴文本，规则切分或交给 AI，一键变成书本 / 分卷 / 章节                  |
| ⚙ 设置  | `#/settings` | API 提供商、模型方案（多套预设一键切换）、全局提示词、内置 prompt 模板、数据导入导出  |

四个内容界面：

| 界面     | 路由                     | 做什么                                                                                               |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------- |
| ① 书架   | `#/books`              | 同上；卡片上有「继续 第N章」直达按钮                                                                               |
| ② 书本编辑 | `#/book/{id}/{tab}`    | 基本信息、世界设定（全局 / 分卷作用域）、章节目录、提示词挂载、记忆、数据；六个标签固定展示不滚动                                                |
| ③ 章节目录 | `#/book/{id}/chapters` | 书本编辑的「章节目录」标签页即完整目录：按分卷分组、卷可收起 / 打开、整行点击进入章节，AI 自动分章、AI 重写（原 `#/chapters/{id}` 独立页已移除，老链接自动改写到这里） |
| ④ 阅读   | `#/read/{id}/{cid}`    | 上下滑动翻页、AI 流式写作 / 重写、撤回、字号、行高 / 段间距 / 主题、进度百分比、键盘翻章                                                |

翻页：在阅读页上下滑动到顶/底继续拖即可切换章节，也可以用底部按钮；翻页不会退回章节列表。

「最近」页的进度在以下时机自动更新：进入阅读页、上下翻页、手动编辑正文、编辑章节大纲。

## 功能细节

**API 提供商（只管连接）**

- 模型名 / 温度 / maxTokens 不在提供商里配，统一在下方「模型方案」中管理，避免两处重复
- 接口类型：`OpenAI 兼容`（OpenAI / DeepSeek / Moonshot / 智谱 / 硅基流动 / 阿里百炼 / 火山 / Ollama / 一切 one-api 类网关）、`Anthropic Claude`、`Google Gemini`、`自定义`
- 内置 9 个预设，点一下自动填 Base URL 和模型名，只填 Key 即可
- 支持流式输出（写作时逐字显示，可随时「中止」并保留已生成内容）
- 可填自定义请求头，支持中转 / 反代
- **📥 拉取模型列表**：按接口类型拉取提供方的模型列表，注入当前表单内点选（带筛选），不用手写模型名
- **💰 查询余额**：DeepSeek / Moonshot / 硅基流动等按域名自动识别余额端点，也可自定义「余额查询地址」；无公开接口的提供商明确提示去官网后台

**模型方案（多套预设）**

- 每套方案 = 一个提供商 + 指定模型 + 可选温度 / maxTokens 覆盖
- 设置页集中管理（新增 / 编辑 / 删除 / 启用），右下角**悬浮球**里也能一键切换
- 所有 AI 生成都用当前启用的方案；老数据自动迁移出一个默认预设，行为与之前一致
- 温度 / maxTokens 留空时用默认值（0.85 / 4096），也可只覆盖其中一项

**全局提示词（按条管理）**

- 设置页里增删改、上下调顺序、单独停用
- 每本书独立开关「挂载」，两处都开才注入
- 新建的提示词默认挂载到所有书本

**书本内设定（世界书，可缺省）**

- 分栏：背景设定 / 人物 / 地点 / 概念·设定 / 势力·组织
- 每条 = 名称 + 内容，可单独停用；**空栏不会被注入**，不浪费 token
- **全局 / 分卷作用域**：设定分「全局」（全书生效）与「分卷专属」（只对该卷章节生成时注入）两种，世界设定页顶部 chips 切换；条目的归属随时可改——编辑表单里有「归属」下拉，分卷视图下点全局条目即可把它挪到本卷，或「↧ 复制到本卷」留一份单独改写。章节目录页与阅读页菜单都有「🌍 浏览世界设定」入口
- 另有书本级的「额外要求」，每次生成都会带上
- **✨ AI 整理**：懒得一条条填时，点它把一大段想法一股脑倒进去，AI 会自动拆成若干条目归到对应分栏；识别结果先列出来让你勾选，同名条目会合并更新而不是重复新建
- **💡 AI 推荐**：写章节 / 生成记忆时 AI 顺手记下的新设定会先放在这里等你确认（书本 Tab 上有 `💡N` 角标）；「✓ 转正」进对应分栏、「✎ 改后转正」可改名称内容和分栏、「忽略」丢弃，也能「☑ 选择并转正」批量挑。已存在的设定不会被重复推荐

**分卷 ↔ 章节（父子结构）**

- 每一章都必须属于某个分卷，不存在「无分卷的章节」：新建章节、AI 分章时都会强制选分卷；这本书还没有分卷时会先引导你建一个
- 章节目录按分卷分组，**点卷标题可收起 / 打开该卷章节**；卷头可以直接「✨ 自动分章」「＋ 本卷新章」「✎ 卷大纲」
- **整行点击进入章节**：章节行除功能按钮外的任意位置（含章节号）点击即进入阅读 / 写作
- **换分卷**：章节卡片上的「⇄ 换分卷」（章节菜单里也有）可以把这一章挪到别的分卷末尾，正文与大纲不受影响；编辑章节时也能改所属分卷
- **删除分卷**：若该卷下还有章节，会让你选「移到其他分卷」或「连同章节一起删除」，不会留下无分卷的孤儿章节
- 旧数据打开时会自动归入第一卷

**快捷导入（底栏 📥）**

- 粘贴文本 → 预览 → 导入，书本 / 分卷 / 章节一次生成
- **规则切分（免费、不用 API）**：按发言标记切分。`【我】: xxx` 的内容进「章节大纲」（即当时你给 AI 的指令），`【AI名】: xxx` 的内容进「章节正文」。适合 OMate 之类只能导出聊天记录的软件。除了自动剔除导出尾巴（"分享自 xxx"）和结尾追问（"需要继续下一章吗？"），还会去掉 markdown 标题并从中提取章节标题。
  - 「我的发言标记」可自定义（默认「我」），AI 的代号不固定也没关系，只要不是你自己的标记就都算正文
  - 全部章节归入同一个分卷，分卷名可改
- **AI 整理**：整段交给模型，让它自己识别书名、简介、分卷与章节（可勾选「同时提取正文」，长文本不建议）
- 文本源：手动粘贴 / 剪贴板 / 选择本地 `.txt` 文件；草稿会自动保存，切页面不丢
- 可以选择「新建一本新书」或「追加到已有书本」

**大纲与分章**

1. 在「章节目录」里点卷头的「✎ 卷大纲」写一卷的大纲
2. 点「✨ 自动分章」，选分卷、填章节数（比如 8）
3. AI 返回 8 段章节大纲 + 标题，生成完自动刷新章节目录
   - 分章时给 AI 的上下文是四段：**世界设定 + 完整长期记忆 + 最近 3 章正文全文 + 本卷大纲**（不再列举其他分卷的大纲，避免串卷、也省 token；长期记忆是摘要 + 全部章节记忆条目，不受「注入最近几条」限制；正文取全书最后 3 个已写章节，原样全文不截断）
   - 默认「追加到本卷末尾」；**取消勾选则是「清空本卷现有章节后重写」，只影响当前分卷**，其他分卷的章节、正文、记忆一律不动（会先弹确认告诉你要删几章）
4. 章节行上「✎ 大纲」随时改（点大纲文字也可以），「✨ 生成正文」直接开写
5. 进入任意章节点「✨ AI 写」，按本章大纲生成正文；**已有正文的章节，按钮变为「✏️ AI 重写」**——可填「重写指示」；**不填也能重写**（等于不加额外要求重写一遍），完成后 toast 里可一键撤销

**内置提示词模板（可多套方案）**

- 设置 → 「✎ 编辑内置 prompt」，共 12 处内置措辞：输出规范、书籍信息块、世界设定块、分卷大纲块、正文主提示词、记忆注入块、记忆注入块 · 完整版、分卷自动分章、单章大纲、记忆总结+设定推荐、世界设定 AI 整理、文本快捷导入
- 「分卷自动分章」的占位符为 `{{bookInfo}} {{world}} {{memory}} {{recentContent}} {{volume}} {{count}}`（书籍信息 / 世界设定 / 完整长期记忆 / 最近 3 章正文全文 / 本卷大纲 / 章节数）
- 每处可保存多套方案：复制 / 新增 / 改名 / 编辑 / 删除 / 一键切换启用 / 恢复内置默认
- 用 `{{占位符}}` 组装，页面里会列出该模板可用的占位符；**删掉某个占位符就等于不注入那部分内容**（想省 token 就把「世界设定」「记忆」之类删掉）

正文生成时会自动带上：书籍信息 + 世界设定 + 分卷大纲 + 完整长期记忆（摘要 + 全部章节记忆条目）+ 前几章正文全文（最近 3 章，原样不截断）+ 本章大纲。

**记忆系统**

- 记忆页可完整查看长期摘要，「🔍 查看实际注入内容」能看到真正发给模型的那段记忆（可复制）
- 摘要和每一条章节记忆都能手动编辑；「注入最近几条」可现场调
- 每章写完后自动总结，产出「本章要点」+ 更新后的「长期记忆摘要」
- 下次生成时注入：长期摘要 + 最近 N 条章节要点（N 可调）
- 撤回 AI 生成时，正文回滚、本次写入的记忆条目删除、长期摘要恢复到生成前的版本（顺带推荐出来的设定也一并撤回）
- 也可以手动添加 / 删除 / 编辑记忆
- **💡 AI 顺带推荐新设定**：写章节 / 重新生成记忆时，AI 会一并挑出本章出现的新人物、地点、概念等。**不会直接写进世界书**，只在底部弹一条轻提示「AI 推荐了 N 条新设定 / 去看看」；去「世界设定」页即可逐条「✓ 转正」「✎ 改后转正」（可换分栏）或忽略，也支持「☑ 选择并转正」勾选批量处理。同名条目转正时追加合并，已存在的设定不会被重复推荐。可在记忆页用「顺带推荐新设定」开关关掉
- **🔁 重新生成记忆**：勾选要处理的章节后按章节顺序重新总结并依次合并进长期摘要。**默认只勾选「还没有记忆」的章节**，正好用来给导入的小说补记忆；也可以「全选」或只选某几章重来（重来时会先移除该章的旧记忆，不会重复累积）

## 新增功能（v2）

**🔍 全文搜索**

- 书架顶部常驻搜索框，输入即搜（180ms 防抖），覆盖章节标题 / 大纲 / 正文、世界设定、长期记忆与章节记忆、书名简介
- 按相关度排序（书名 > 标题大纲 > 世界设定 > 正文记忆），命中词 `<mark>` 高亮，同一章只出一条
- 点结果直接跳到该章；可限定搜索范围（正文 / 设定 / 记忆）

**🎨 三套主题**

- 暗色（默认）/ 亮色 / 护眼纸黄，设置页一键切换，选择会被记住
- 浏览器地址栏颜色（`theme-color`）跟随主题

**📖 阅读排版**

- 阅读页 ⋮ 菜单里调：行高、段间距、主题，实时生效
- 阅读工具条显示连续阅读进度（章进度 + 章内滚动位置合成的百分比）与本章字数

**📊 写作统计**

- 书本数据页入口：总字数、已写章节、完成度、平均章字数四宫格 + 分卷明细表 + 待写章节列表

**📤 导出增强**

- TXT 导出可选：带分卷结构 / 附章节大纲 / 只导出已写章节
- 新增 Markdown 导出：分卷标题、章节标题、大纲以注释形式保留

**⌨️ 键盘快捷键**（桌面端）

- `←` / `→` / `PageUp` / `PageDown`：阅读页翻章
- `Ctrl/Cmd + S`：保存；`Ctrl/Cmd + K`：聚焦书架搜索框；`Esc`：关闭面板 / 退出全屏编辑器

## 新增功能（v3）

**📥 模型列表拉取 + 💰 余额查询**

- 模型方案表单里一键拉取提供方的模型列表（按 OpenAI 兼容 / Anthropic / Google 三家端点分别适配；连接参数取自所选提供商），列表注入当前面板、带筛选、点选即填入
- 余额查询按域名自动识别端点（DeepSeek / Moonshot / 硅基流动），也支持自定义「余额查询地址」；常见余额字段自动穷举识别

**🔀 多模型方案（预设）**

- 配置多套「提供商 + 模型 + 参数覆盖」方案，设置页管理，悬浮球一键切换
- 比如：DeepSeek 写正文、Kimi 整理大纲、便宜模型跑记忆总结，随时换

**📑 标签页固定 + 章节目录**

- 书本编辑页六个标签完整展示、自动换行，不再横向滚动和「自动回正」
- 原「大纲分卷」与章节列表合并为**章节目录**：按分卷分组、卷可收起 / 打开、整行点击进入章节

**🌍 世界设定作用域**

- 设定分全局 / 分卷专属，生成时只注入「全局 + 本章所属分卷」，其他分卷的专属设定不进上下文
- 章节目录页、阅读页菜单都能「🌍 浏览世界设定」

**✏️ AI 重写**

- 已有正文时生成按钮变为「AI 重写」，可填「重写指示」（如：加快节奏、把结尾悬念写明确）；**留空同样执行**，只是不加额外要求
- 完成后 toast 一键撤销（正文、记忆、顺带推荐的设定一起回滚）

**◆ 可拖动悬浮球**

- 右下角圆形按钮，可拖动（位置自动记住）；**点一下只出选项面板**，再点面板里的功能才执行（面板不会挡住球，点不同区域效果一致）
- **↩ 撤销上次生成**：全局随手可用的后悔药。正文生成 / AI 重写 / 划线改稿 / 小编改动，哪一件最近就退哪一件，确认框里会写明是哪一章、什么时候做的、退回去会发生什么。不在书本页时会自动在全部作品里找最近的那一次。两类记录同时存在时（比如刚生成完又让小编改了设定）会列出来让你选，而不是替你猜
- **查看最近 AI 上下文**：系统保留最近 3 次请求（正文生成 / 记忆整理等各占一条、互不覆盖），面板顶部可逐条切换；显示完整上行（地址 / 请求头 / 请求体），密钥自动脱敏、可复制——用来核对「AI 到底看到了什么」
- **切换模型预设**：列出全部方案，点选即切换

## 新增功能（v4）

**🧹 提供商与模型方案合并（去重）**

- 提供商只管连接（名称 / 类型 / Base URL / Key / 请求头 / 余额地址），模型与参数统一归「模型方案」，界面不再有两处重复配置
- 老数据自动为每个提供商补建默认方案，原样搬迁模型与参数，行为不变；新增提供商保存后自动引导建第一个方案

**🔧 世界设定归属随手改**

- 条目编辑表单新增「归属（全局 / 分卷）」下拉，随时在全局与各分卷之间挪动
- 分卷视图下全局条目可点开编辑（改归属），或「↧ 复制到本卷」生成专属副本单独改写
- AI 推荐的「✎ 改后转正」同样支持选归属

**◆ 悬浮球交互修正**

- 修复「点一下直接进查看上下文、第二次才出选项、点不同区域效果不同」：根因是面板在 `display:none` 态被测量（高度为 0）而盖住了悬浮球，随后的点击落到面板第一个按钮上
- 现在先显示再定位（面板绝不遮挡球），开合统一由点击触发，拖动（位移 > 8px）不触发且拖动后的点击被忽略

**📋 上下文记录升级为最近 3 条**

- 环形缓冲保留最近 3 次请求，每次带类型标记（正文生成 / AI 重写 / 记忆整理 / 自动分章 / 章节大纲 / 设定整理 / 文本导入）
- 生成正文后紧接着的记忆整理不再覆盖正文的上下文，面板顶部一条切换条逐条查看

**📑 章节目录双入口合并**

- `#/chapters/{id}` 独立目录页移除，老链接 / 书签访问时自动改写为书本编辑的「章节目录」标签页（不新增历史记录）
- 独立页原有的「🌍 浏览世界设定 / ✨ AI 自动分章 / ＋ 新建章节」全部并入标签页（内容区按钮行 + 顶栏）

## 新增功能（v6）：成本与连续性

这一轮对着「长文本连续性 / Token 成本 / 易用度 / Prompt 参考准确性」四项做的专项改造。

**💰 用量记账：看得见钱花在哪**

- 每次请求结束把接口返回的 `usage` 记进「全局 + 本书」两本账：请求次数、输入 / 输出 token、缓存命中 token
- 三家字段统一归一（OpenAI `prompt_tokens` / Anthropic `input_tokens` / Gemini `promptTokenCount`）；Anthropic 流式的输入 token 藏在 `message_start.message.usage` 里，一并接住
- 在「设置 → 模型方案」里给方案填单价（元 / 百万 token）后自动估算成本；没填就只显示 token，不假装有金额
- 设置页与书本「数据」页都有用量卡片，可一键清零

**🧠 任务级模型路由 + 关闭思考**

- 十类任务各自可以指派一套方案：正文生成 / **小编对话** / 标记处局部修改 / 自动分章 / 单章大纲 / 记忆总结 / 设定管理 / 设定整理 / 一致性审计 / 文本导入
- 设置页有「**任务分工**」一览表，逐行列出每类活实际会走哪套方案，标出「专职 / 用兜底」，冲突（同一任务被多套认领）和失效（指派的那套提供商已删除）也会提示
- 每行右侧「**指派…**」直接指定该类任务用哪套方案（或改回用兜底），不用去记哪套方案绑了什么
- 记忆整理、审计这类「杂活」指到便宜模型上，正文继续用旗舰——这是省成本最立竿见影的一刀
- **「启用 / 兜底方案」只有一个，但它只管没有单独指派的任务**；已指派专职的任务不受它影响（悬浮球里切换的也是兜底方案）
- 方案里可勾「关闭思考」：OpenAI 系发 `enable_thinking:false` + `thinking:{type:'disabled'}`，Gemini 发 `thinkingConfig.thinkingBudget:0`；思考 token 是按输出计费的，写正文时能省一大截
- 老网关不认这些新参数会返回 400，此时自动剥掉对应参数重试（流式仍是流式），不会直接失败

**🎯 世界设定触发式注入 + 角色卡**

- 设定条目可填「触发词（别名）」，本章大纲 / 标题 / 长期摘要 / 上一章结尾里没出现的设定就不进上下文；勾选「📌 常驻」则无视关键词始终注入
- **没填关键词的条目行为完全不变**（始终注入），老数据无感升级；分章等需要通盘上下文的任务按「全部注入」处理
- 人物条目新增结构化字段：状态 / 位置 / 目标 / 已知 / 关系，注入时附在内容后面——模型写连续剧情时不用猜「他现在在哪、他知道什么」

**⏱️ 只给模型看「本章之前」**

- 写第 N 章时，上下文一律以第 N 章为界：其后的正文全文、其后的章节记忆要点、本章自身的旧正文与旧要点都不注入
- 长期摘要会自动**回溯到写这一章之前的版本**（记忆条目里存着当时的摘要快照）；回溯不到时退回最新摘要，并在提示词里明确标注「不得提前写出后续剧情」
- 还没埋到本章的伏笔（埋设章晚于当前章）也不列出
- 回头修改前面的分卷 / 章节时，模型不会被后文牵着走——这是「改旧章越改越像补叙」的根因
- 生成前预览会写明「你在修改第 X 章，其后的 N 章正文、M 条记忆不注入」，不会让你以为记忆丢了
- 自动分章这类「追加到书末尾」的任务不受影响，仍然通盘了解全部前情

**🔁 重写同一章不会吃自己的旧记忆**

- 长期摘要是滚动累积的，写第 N 章后它已经含第 N 章。重写时拿它当「前情」喂回去，等于让模型照着这章的旧版重写，越改越像自己抄自己
- 现在写 / 重写第 N 章时，前情摘要一律回溯到**写这一章之前**那一刻（记忆条目里存着当时的快照）
- **一章只留一条记忆**：反复重写不会给同一章攒出多份互相矛盾的记忆；记忆条的「写这一章之前的摘要」快照也保留最早那次，不被后续重写污染
- 撤回也修好了：重写后点「撤回」会把这章的记忆**恢复**成重写前的版本，而不是把它删掉
- 已经攒过重复记忆的书，打开即自动合并成一条（内容取最新、快照取最早）

**✂️ 同一段剧情不付两次钱**

- 最近 3 章正文是全文注入的，那么这 3 章的记忆要点就不再重复列出（此前等于同一段剧情既买了全文又买了摘要）
- 勾掉「最近正文」时记忆自动恢复完整，信息不会丢

**🪝 伏笔板**

- 书本新增「伏笔」标签页：内容 / 埋设章 / 计划回收章 / 状态 / 备注，支持编辑、标记回收、重新开启、删除
- 未回收的伏笔会随正文生成自动注入提示词（提醒模型写到该收的地方接住，未到计划章别提前揭开）
- 写到第 N 章还没回收的，列表里高亮「⚠ 逾期未回收」，标签页上带角标——长线伏笔烂尾，绝大多数不是忘了写，是忘了还没收

**💬 AI 小编（对话式）**

- 书本页新增「小编」页签：像跟真人编辑聊稿一样讨论剧情、让它挑毛病、让它帮你改数据
- **它看到的上下文和写正文时是同一份**——世界设定 / 前情记忆 / 本章之前的正文 / 伏笔 / 文风规则 / 分卷大纲。不用另建知识库，小编对项目的了解和写作模型完全一致
- 上下文以某一章为基准（默认最近一章），顶部可切换；也正因为沿用同一套截断逻辑，小编不会拿到本章之后的内容
- **它不直接改你的书**。要动数据时，它在回复末尾写上标签块：

  ```
  [改设定 老周]
  铁匠；实为北境守夜人的眼线，铜哨是接头信物
  [/改设定]

  [加伏笔 3 9]
  老周腰间的铜哨
  [/加伏笔]

  [改大纲 5 夜访]
  林昭夜访铁匠铺，第一次见到铜哨
  [/改大纲]
  ```

- 每个标签在对话里渲染成一张卡片，**逐条**可以**预览**（展开看完整的前后对照）、**修改**（改完再应用）、**应用**、**忽略**；也能一次「全部应用」
- 定位用的名称必须和世界书里的原文对得上；名字有重名、找不到条目时，那条会标成「不适用」并说明原因——**绝不猜着改**
- 每次应用记一条事务，界面上留一条「已应用 · 撤销」；单条应用和整批应用都能各自退回
- 七种标签：加设定 / 改设定 / 删设定 / 加伏笔 / 改伏笔 / 改大纲 / 改分卷
- 这是**一类独立的模型任务**（「小编对话 / 改稿提案」），可以用便宜模型专门跑

**🖍 框选改稿（只改框住的地方）**

- 在正文编辑里用 **【【】】** 把要改的地方框起来，保存后系统自动识别成一处处条目：

  ```
  雨点砸在石板路上，他没有撑伞，【【连鞋都没湿】】。
  ```

- 阅读页把框里的字高亮显示（**方括号本身不出现**，读者看不到），阅读条上出现「🖍 N」
- 点「🖍 N」打开面板：**每个框一条**，意见框就嵌在条目下面（不是全屏弹窗），填完直接点「✨ 按意见修改」
- AI **只重写框里的内容**，本章其余部分一个字不动；应用后方括号自动去掉，成稿里不会留下标记
- 不用浏览器选区——选区的 DOM 范围与原文偏移换算在移动端（换行、软键盘、手势翻页叠加）太不可靠；框选是纯文本层面的，所见即所得
- 意见按**框里的原文**对齐，所以作者随手改正文（加字、删段、调顺序）都不会让意见错位；框删掉了，它的意见也跟着清掉
- 「取消标记」= 去掉所有方括号（框里的字保留）+ 清空意见，这一步也能撤销
- 跟「AI 重写」的区别：重写是整章重来，这里是外科手术。适合定稿阶段的精修
- 这是**一类独立的模型任务**（「标记处局部修改」），可以单独指派模型
- 应用后会存快照，一键「撤销」就能回到改之前
- 正文被整章重新生成后，对不上的标记不会乱改地方——它会标成「定位不到」等你处理，绝不会改错位置

**🗂️ 设定管理模型（新增 / 修改分开处理）**

- 记忆模型看不到世界书，它挑出来的「新设定」里必然混着一堆其实已经有了的。现在多一道工序：**设定管理**模型对照世界书整理一遍
- 它拿到的是带 id 的现有条目清单，因此能分清两件事：
  - **新增**：确实是新对象 → 进推荐列表，等待转正（还能顺手补上别名 / 触发词）
  - **修改**：其实已有对应条目，只是本章给了新事实 → 输出**合并后的完整内容**，标「改」
- 修改型建议在世界设定页显示「原内容 → 新内容」对照和理由，确认后才写回原条目（世界书不会被 AI 直接改写），也不会多出重复条目
- 这是一类**独立的模型任务**（「设定管理（去重与修改）」），可以在「设置 → 任务分工」里单独指派，比如用一个便宜但严谨的模型
- 记忆页可关掉这道工序（省一次请求），关掉就用记忆模型的原始候选

**🖋️ 文风规则**

- 书本基本信息页可填「禁用词清单」，写正文时作为独立区块注入
- 生成后自动做一次**本地扫描**（零 API 成本），命中禁词时 toast 提示并可跳转查看

**🔍 生成前预览 + 写后一致性审计**

- 点生成先弹「本次将注入 · 粗估 N token」：六块内容（世界设定 / 前情记忆 / 最近 3 章正文 / 伏笔 / 文风规则 / 分卷大纲）各自列出条数、字数、粗估 token
- 每块可临时勾掉——省 token 或做「人工策稿」（关键章手动决定给模型看什么）。设置 → 数据里可关闭预览
- 阅读页 ⋮ 菜单新增「🔍 一致性审计」：对照世界设定与前情记忆，逐条报出正文原句、冲突的设定、修改建议（走独立的 audit 模型，手动触发，不自动烧钱）

**📦 PWA 与单文件版**

- 新增 `manifest.webmanifest` + `sw.js`：可「添加到主屏幕」离线打开
- 缓存策略是**同源 network-first**：先回源（`cache: 'reload'` 绕开 HTTP 缓存），网络不通才回落到缓存，导航请求再退到 `index.html`。
  不用 stale-while-revalidate —— 「先给缓存」会让 `git pull` 之后第一次打开必定是旧版，而且那个后台重验证会被浏览器的 HTTP 缓存
  喂回旧字节（`python3 -m http.server` 不发 `Cache-Control`，浏览器按启发式规则认为旧文件还新鲜），手机上表现为「pull 了却看不到新功能」
- **改了代码看不到新功能时**：到「设置 → 版本与更新」点「↻ 强制刷新（清缓存重载）」——注销 SW、清掉全部 Cache Storage 再带 cache-busting 参数重载，
  **只清缓存，作品数据一条都不掉**。设置页同时显示当前版本号，方便和 sw.js 里的 `VERSION` 对一眼
- 加载时会主动 `registration.update()`：浏览器平时只在导航时顺带检查 `sw.js`，手机切回来打开经常正好跳过那一步
- `node build/single-file.js` 生成 `dist/index.html`（约 350 KB，css / js / 图标全部内联），双击就能用，适合手机上直接打开或发给别人

**🛡️ 存储加固**

- 撤回栈封顶 10 条（快照含整章旧正文，长篇下 30 条会吃掉可观空间）
- 书本菜单新增「📦 归档导出」：导出后从本机移除，给 localStorage 腾地方

## 新增（v6.1）：并发与稳定性

**🔒 AI 任务互斥锁**

- 同一时刻只允许一个 AI 请求在跑。正文生成 / 重写、自动分章、一致性审计、单章大纲、设定整理、重新生成记忆、AI 整理导入结构——七个会改数据的入口全部加锁；设置页的测试连接 / 拉取模型列表 / 查询余额也走同一把锁（它们不写章节，但会抢共用的忙碌浮层，把正在进行的生成浮层和「停止」按钮一起关掉）
- 任务进行中再点别的 AI 按钮，不会新开一个请求，而是提示「『XX』正在进行，请先点『停止』结束它，再开始新的」
- 每个长任务都有独立的 `AbortController`，忙碌弹层上的「停止」能真正中断请求（此前只有一个全局 abort，覆盖面不全）
- 兜底保护：锁超过 15 分钟未释放会被强制放行，避免一次异常让整个应用再也开不了工

**📜 流式自动跟随**

- 正文流式输出时默认自动滚到底部；你手动向上翻页时**自动暂停**跟随，右下角浮出「跟随 ↓」按钮
- 点按钮（或自己滚回底部）即恢复自动滚动，流式结束后按钮自动收起
- 记忆阶段不再抢滚动条——只有正文生成会跟随

**🐛 修复**

- **开关记忆后界面不及时更新**：开关现在会写回书本并立即重渲染，书架副标题的「记忆开 / 记忆关」同步刷新
- **生成结束后报 `body stream already read`**：`Response` 的 body 只能读一次，400 兜底重试里读了两次。改为只读一次、每次重试重置，重试结束仍失败才读错误文案
- **Anthropic 输入 token 漏记**：输入 token 在 `message_start.message.usage`，顶层 `usage` 只有输出
- 单文件版图标此前仍是外链（`file://` 下 404），现改为 base64 内联

```bash
node tests/smoke.js      # 数据层、提示词、SSE 解析、搜索、工具函数边界
node tests/dom.js        # 完整业务流程端到端
```

## 数据备份

设置页 → 数据 → 「导出全部数据」会下载一个 JSON（含接口配置、提示词、全部作品、章节、记忆）。  
`localStorage` 会被「清除浏览器数据」清掉，重要作品请定期导出。

保存策略：首次保存时写一份基线副本到 `novel_ai_db_v1_bak`，之后**不会**被后续保存覆盖——所以它始终是「第一次成功保存时的完整快照」，主存储损坏时用它恢复。主存储解析失败时会自动尝试从备份恢复并在界面提示；两者都损坏时应用会明确报错并给「导出原始数据」的抢救入口，不会静默清空你的书架。保存失败（多为存储空间满）时界面上会有常驻警告，数据页也会显示本地占用。

## 已知限制

- 数据仍存在 `localStorage`（多数浏览器上限约 5 MB）。超长篇建议定期用书本菜单的「📦 归档导出」把完结的书导出后从本机移除；迁移到 IndexedDB 属于高风险改造，暂时没做
- 单章正文很长时，发给模型的上下文会变大；可通过世界书停用、调小「最近记忆条数」、在生成前预览里临时勾掉某几块来控制成本
- 用量成本是「按方案单价估算」，缓存命中的折扣没有计入（宁可高估）；真实账单以网关侧为准
- Google Gemini 走 SSE 流式；若你用的网关不支持流式，OpenAI 兼容类型会自动降级为一次性返回
- 拉取模型列表需要提供商开放 `/models` 端点（部分网关不开放，此时只能手写模型名）；余额查询同理，不支持的提供商会明确提示
- 悬浮球位置按「屏幕坐标」记忆，极少数浏览器在软键盘弹出后位置可能略偏，拖动一下即可
- 上下文记录只保留最近 3 次（临时查看用），更早的请求不落盘；需要长期审计请自行在网关侧查看
- 「AI 自动分章」会带上完整长期记忆与最近 3 章正文全文，写得多了这个请求会比较大（这是为了分章接得住前文）；嫌贵可以先在「记忆」页精简章节记忆条目
- 「AI 重写」会根据本章大纲、前情记忆与上一章结尾重新写一遍；**重写指示不会让模型「逐句改写原文」**——当前注入的上下文里不含本章已有正文，重写等于换个角度重新生成（想保留原作请先手动复制一份）


- 没有服务端，换设备只能靠导出 / 导入 JSON
