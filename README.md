# AI 小说写作助手（纯静态 HTML 版）

一个不用装 SDK、不用编译的单页 Web App：手机浏览器打开就能用，所有数据存在本机 localStorage，API Key 只保存在你自己的设备上。

## 在 Termux / 手机上跑起来

```bash
cd novel-writer
python3 -m http.server 8080
# 手机浏览器打开 http://127.0.0.1:8080
```

或者任意静态服务器（`npx serve`、`busybox httpd -p 8080` 都行）。
也可以直接用浏览器打开 `index.html`，但部分浏览器对 `file://` 页面的本地存储有限制，**建议用 http 方式访问**（Termux 里一条命令即可）。

> 手机和 Termux 是同一台设备，所以 `127.0.0.1` 就能访问。若要在电脑上访问手机上的服务，用 `python3 -m http.server 8080 --bind 0.0.0.0`，然后访问手机局域网 IP。

## 底部主导航

底部常驻三个分页按钮（阅读页自动隐藏，把底部让给阅读工具条）：

| 按钮 | 路由 | 做什么 |
| --- | --- | --- |
| 📚 书架 | `#/books` | 新建 / 选择书本，菜单可重命名、复制、导出、删除 |
| 🕘 最近 | `#/recent` | 每本书一张卡片，记住你最近阅读或编辑的那一章，点一下直接回到该处 |
| 📥 导入 | `#/import` | 粘贴文本，规则切分或交给 AI，一键变成书本 / 分卷 / 章节 |
| ⚙ 设置 | `#/settings` | API 提供商、全局提示词、内置 prompt 模板、数据导入导出 |

四个内容界面：

| 界面 | 路由 | 做什么 |
| --- | --- | --- |
| ① 书架 | `#/books` | 同上；卡片上有「继续 第N章」直达按钮 |
| ② 书本编辑 | `#/book/{id}/{tab}` | 基本信息、世界设定、大纲分卷、提示词挂载、记忆、数据 |
| ③ 章节列表 | `#/chapters/{id}` | 章节增删改排序、AI 自动分章、进入写作 |
| ④ 阅读 | `#/read/{id}/{cid}` | 上下滑动翻页、AI 流式写作、撤回、字号 |

翻页：在阅读页上下滑动到顶/底继续拖即可切换章节，也可以用底部按钮；翻页不会退回章节列表。

「最近」页的进度在以下时机自动更新：进入阅读页、上下翻页、手动编辑正文、编辑章节大纲。

## 功能细节

**API 提供商**
- 接口类型：`OpenAI 兼容`（OpenAI / DeepSeek / Moonshot / 智谱 / 硅基流动 / 阿里百炼 / 火山 / Ollama / 一切 one-api 类网关）、`Anthropic Claude`、`Google Gemini`、`自定义`
- 内置 9 个预设，点一下自动填 Base URL 和模型名，只填 Key 即可
- 支持流式输出（写作时逐字显示，可随时「中止」并保留已生成内容）
- 可填自定义请求头，支持中转 / 反代

**全局提示词（按条管理）**
- 设置页里增删改、上下调顺序、单独停用
- 每本书独立开关「挂载」，两处都开才注入
- 新建的提示词默认挂载到所有书本

**书本内设定（世界书，可缺省）**
- 分栏：背景设定 / 人物 / 地点 / 概念·设定 / 势力·组织
- 每条 = 名称 + 内容，可单独停用；**空栏不会被注入**，不浪费 token
- 另有书本级的「额外要求」，每次生成都会带上
- **✨ AI 整理**：懒得一条条填时，点它把一大段想法一股脑倒进去，AI 会自动拆成若干条目归到对应分栏；识别结果先列出来让你勾选，同名条目会合并更新而不是重复新建
- **💡 AI 推荐**：写章节 / 生成记忆时 AI 顺手记下的新设定会先放在这里等你确认（书本 Tab 上有 `💡N` 角标）；「✓ 转正」进对应分栏、「✎ 改后转正」可改名称内容和分栏、「忽略」丢弃，也能「☑ 选择并转正」批量挑。已存在的设定不会被重复推荐

**分卷 ↔ 章节（父子结构）**
- 每一章都必须属于某个分卷，不存在「无分卷的章节」：新建章节、AI 分章时都会强制选分卷；这本书还没有分卷时会先引导你建一个
- 章节列表按分卷分组，卷头可以直接「✨ 自动分章」「＋ 本卷新章」「✎ 卷大纲」
- **换分卷**：章节卡片上的「⇄ 换分卷」（章节菜单里也有）可以把这一章挪到别的分卷末尾，正文与大纲不受影响；编辑章节时也能改所属分卷
- **删除分卷**：若该卷下还有章节，会让你选「移到其他分卷」或「连同章节一起删除」，不会留下无分卷的孤儿章节
- 旧数据打开时会自动归入第一卷

**快捷导入（底栏 📥）**
- 粘贴文本 → 预览 → 导入，书本 / 分卷 / 章节一次生成
- **规则切分（免费、不用 API）**：按发言标记切分。`【我】: xxx` 的内容进「章节大纲」（即当时你给 AI 的指令），`【AI名】: xxx` 的内容进「章节正文」。适合 OMate 之类只能导出聊天记录的软件。除了自动剔除导出尾巴（"分享自 xxx"）和结尾追问（"需要继续下一章吗？"），还会去掉 markdown 标题并从中提取章节标题。
  - 「我的发言标记」可自定义（默认「我」），AI 的代号不固定也没关系，只要不是你自己的标记就都算正文
  - 全部章节归入同一个分卷，分卷名可改
- **AI 整理**：整段交给模型，让它自己识别书名、简介、分卷与章节（可勾选「同时提取正文」，长文本不建议）
- 文本源：手动粘贴 / 剪贴板 / 选择本地 `.txt` 文件；草稿会自动保存，切页面不丢
- 可以选择「新建一本新书」或「追加到已有书本」

**大纲与分章**
1. 在「大纲分卷」里写一卷的大纲
2. 点「✨ 自动分章」，选分卷、填章节数（比如 8）
3. AI 返回 8 段章节大纲 + 标题，生成完自动刷新章节列表
   - 默认「追加到本卷末尾」；**取消勾选则是「清空本卷现有章节后重写」，只影响当前分卷**，其他分卷的章节、正文、记忆一律不动（会先弹确认告诉你要删几章）
4. 章节卡片上「✎ 大纲」随时改（点大纲文字也可以），「✨ 生成正文」直接开写
5. 进入任意章节点「✨ AI 写」，按本章大纲生成正文

**内置提示词模板（可多套方案）**
- 设置 → 「✎ 编辑内置 prompt」，共 11 处内置措辞：输出规范、书籍信息块、世界设定块、分卷大纲块、正文主提示词、记忆注入块、分卷自动分章、单章大纲、记忆总结+设定推荐、世界设定 AI 整理、文本快捷导入
- 每处可保存多套方案：复制 / 新增 / 改名 / 编辑 / 删除 / 一键切换启用 / 恢复内置默认
- 用 `{{占位符}}` 组装，页面里会列出该模板可用的占位符；**删掉某个占位符就等于不注入那部分内容**（想省 token 就把「世界设定」「记忆」之类删掉）

正文生成时会自动带上：书籍信息 + 世界设定 + 分卷大纲 + 前情记忆 + 上一章结尾 1200 字 + 本章大纲。

**记忆系统**
- 记忆页可完整查看长期摘要，「🔍 查看实际注入内容」能看到真正发给模型的那段记忆（可复制）
- 摘要和每一条章节记忆都能手动编辑；「注入最近几条」可现场调
- 每章写完后自动总结，产出「本章要点」+ 更新后的「长期记忆摘要」
- 下次生成时注入：长期摘要 + 最近 N 条章节要点（N 可调）
- 撤回 AI 生成时，正文回滚、本次写入的记忆条目删除、长期摘要恢复到生成前的版本（顺带推荐出来的设定也一并撤回）
- 也可以手动添加 / 删除 / 编辑记忆
- **💡 AI 顺带推荐新设定**：写章节 / 重新生成记忆时，AI 会一并挑出本章出现的新人物、地点、概念等。**不会直接写进世界书**，只在底部弹一条轻提示「AI 推荐了 N 条新设定 / 去看看」；去「世界设定」页即可逐条「✓ 转正」「✎ 改后转正」（可换分栏）或忽略，也支持「☑ 选择并转正」勾选批量处理。同名条目转正时追加合并，已存在的设定不会被重复推荐。可在记忆页用「顺带推荐新设定」开关关掉
- **🔁 重新生成记忆**：勾选要处理的章节后按章节顺序重新总结并依次合并进长期摘要。**默认只勾选「还没有记忆」的章节**，正好用来给导入的小说补记忆；也可以「全选」或只选某几章重来（重来时会先移除该章的旧记忆，不会重复累积）

## 目录结构

```
index.html          页面骨架
css/app.css         样式（移动端优先，暗色）
js/store.js         数据层（localStorage，含自动备份）
js/api.js           多提供商适配 + SSE 流式解析
js/ai.js            提示词组装 / 正文生成 / 章节大纲 / 记忆总结
js/ui.js            界面渲染 + 阅读器手势翻页
js/app.js           路由、事件委托、业务流程
tests/smoke.js      纯 Node 逻辑测试（node tests/smoke.js）
tests/dom.js        jsdom 端到端测试（node tests/dom.js）
```

## 数据备份

设置页 → 数据 → 「导出全部数据」会下载一个 JSON（含接口配置、提示词、全部作品、章节、记忆）。
`localStorage` 会被「清除浏览器数据」清掉，重要作品请定期导出。程序本身每次保存时会自动写一份 `novel_ai_db_v1_bak` 副本。

## 已知限制

- 单章正文很长时，发给模型的上下文会变大；可通过世界书停用、调小「最近记忆条数」控制成本
- Google Gemini 走 SSE 流式；若你用的网关不支持流式，OpenAI 兼容类型会自动降级为一次性返回
- 没有服务端，换设备只能靠导出 / 导入 JSON
